# 六段骨架：逐段写法与样例句

顺序不要调。这个顺序是**读者注意力衰减曲线**定的，不是逻辑完整性定的。

---

## 00｜一句话结论 + 主类比

**目标**：读者只读这一段，也能拿走全部信息。

**结构**

1. 一句反直觉的判断（不是"本文将介绍…"）
2. 主类比登场，一句话说清它对应什么
3. 一句"为什么选这个类比"（可选，但能提高信任）

**样例句**

> 这篇讲的是最基础、也最容易被跳过的一层。如果你不想看字段名和事件名，只想知道它凭什么撑住 20 个部门的生产流量，看这一页就够了。
>
> **先说结论：它是个快递转运中心。**

**反例**

- ❌ "随着大模型技术的发展…"（背景铺垫，没有信息）
- ❌ "本文将从五个方面展开"（目录不是结论）

## 01｜问题有多痛：把它算出来

**目标**：让"为什么需要这一层"从断言变成算术。

**做法**：找到那个**乘法**。绝大多数架构层的存在理由，都是把乘法降成加法。

```
没有中间层：3 种协议 × 20 家渠道 = 60 种适配组合
加了中间层：3 种（左边） + 20 家（右边） = 23
```

然后补一句为什么加法不会爆炸：

> 适配工作量是乘法级别的；加法会慢慢变成瓶颈，但不会像乘法那样爆炸。

**如果没有乘法可算**，退一步用"一次故障的代价"量化：

> 原直连渠道累计被封号 5 次以上，每次都要人工摘号——按每次 2 小时算，一年至少 10 小时纯人工。

## 02–05｜逐层拆

每一层固定三问，**顺序不能反**：

```html
<details class="gate">
  <summary>编号 + 层名 + 一句话钩子</summary>
  <dl>
    <dt>外行版</dt><dd>一句话，不出现术语</dd>
    <dt>没它会怎样</dt><dd>删掉这层，具体坏在哪（最有说服力的部分）</dd>
    <dt>技术上</dt><dd>机制与取舍</dd>
  </dl>
</details>
```

**样例句（"限流"这一层）**

- 外行版：两个维度同时限——一分钟能发多少次请求，一分钟能用掉多少 Token。
- 没它会怎样：一个团队跑个批量任务，就能把整个共享账号池打满。别的部门正常对话突然开始转圈，而且没人知道为什么。
- 技术上：按 app / 用户 / 模型多维度限流，并且要和上游账号的实际配额对齐——限得太松上游会封，限得太紧自己白等。

**关键**：`没它会怎样` 必须具体到"谁在什么场景下遇到什么"。写"影响系统稳定性"等于没写。

用 `<details>` 折叠的原因：非技术读者默认只读 title 行，需要时才展开；技术读者可以一次全开。同一份材料服务两类人。

## 06｜术语对照表

**这段最实用，但最容易被省略。**

```markdown
| 文里的名字 | 它到底在干什么 |
|---|---|
| RainbowBridge | 转运中心大厅，所有请求的统一入口 |
| Director | 转运中心：按目的地规矩改写请求、转换协议 |
```

三个要求：

1. **左边必须是原文里的真实名字**，不能是意译
2. **右边必须是外行话**，不能又是术语
3. **覆盖全文出现过的所有专有名词**——漏一个，读者回去读原文时就卡在那一个上

## 07｜动态全局图

**唯一目的**：把 02–06 所有局部串成一次完整流程，让读者获得"整体感"。

### 六个必做项

| # | 要求 | 为什么 |
|---|---|---|
| 1 | 去程与回程画成**两条不同路线** | 两个方向的难点不同，画成一条就抹平了 |
| 2 | 经过节点时该节点变色 + 图下文字同步切换 | 读者不用回看，视线不离开图 |
| 3 | 一个阶段数组驱动全部 | 加节点只加一条数据，不改动画逻辑 |
| 4 | 进入视口才启动（IntersectionObserver） | 页面一打开就空转，等于没做 |
| 5 | `prefers-reduced-motion` 下关闭动画、一次性画出全路径 | 无障碍硬要求，且不能只是"动画变快" |
| 6 | 提供暂停 / 重放 | 读者要停下来看图 |

### 阶段数组的数据结构

```js
var SEG = [
  { x: 196, t: '出发',       d: '业务方按自己习惯的写法发出请求。',       ids: ['c2'] },
  { x: 232, t: '第一道门 鉴权', d: '刷工牌。认出是谁、哪个应用。',        ids: ['g1'] },
  // …
];
```

`x` 是沿路径的进度阈值，`ids` 是该阶段要高亮的节点 id 列表。**一个阶段可以点亮多个节点**（比如"回执处"同时点亮额度守卫和业务方）。

### 覆盖率自检

术语表里的每一个名字，在动态图上必须有一个可高亮的锚点。

检查方法：把术语表左列和图上文本集合做差集，**必须为空**。有差集说明"正文讲到了，看图找不到"，这是这类页面最常见的断裂。

## 08｜凭什么算「X 级」+ 一句话收尾

**目标**：让决策者拿走一句能对别人复述的话。

**结构**

1. 三条硬指标（不是功能罗列）
2. 一个深色收尾区块，里面放"如果只记一句话"
3. 最后一句用斜体或左边框强调，长度控制在两行内

**样例句**

> 统一桥接真正解决的，不是「协议能不能转」——那是工程问题，迟早能做出来。它解决的是**把不确定性关在中间**。
>
> 这也是为什么它敢让 20 个部门、1.4 万人的流量压上去——因为它保证的不是"更快"，而是"出事的时候，没人需要知道出事了"。

**反例**：❌ "综上所述，该方案具有重大意义。"（无信息量，读者记不住）

## 视觉规范（模板已实现，改内容时别破坏）

| 项 | 值 | 原因 |
|---|---|---|
| 正文栏宽 | 800px | 中文单行 35–45 字，超出后回行困难 |
| 正文字号 | 16.5px | 小于 16px 中文偏小 |
| 行高 | 1.78 | 中文需要比英文更大行距 |
| 强调色 | 单一琥珀色 | 多色强调 = 没有强调 |
| 数字/代码 | 等宽字体 | 与正文形成视觉区分 |
| 信息密集图 | 宽屏外扩 ±160px | 否则 32 个标签缩到 7px，不可读 |

**取舍原则**：宁可让图突破栏宽，也不要把字缩到不可读。留白是为可读性服务的，不是反过来。
